# P3NROSE ゲーム・レベルエディタ仕様書（初版）

## 1. 目的と位置づけ

P3NROSE は、ペンローズ P3 の薄いひし形と厚いひし形で、ステージごとに決められた輪郭の内側を隙間なく埋めるブラウザ向けパズルゲームである。盤面外周には辺のマッチング模様があらかじめ描かれ、プレイヤーはその制約を読みながらタイルを配置する。スコアや時間制限は設けず、完成をステージのクリアとする。

本書は実装開始時の基準仕様とする。Penrosanne はタイル幾何・マッチング規則・立体表現の参考、Symmetrica は初回導線・ステージ選択・開発者画面と公開ステージデータの関係の参考とする。両作品のファイルは参照のみとし、P3NROSE の実装とデータはこのフォルダ内で独立させる。

## 2. 遊びの流れ

1. 初回起動時はタイトルを経由せず、最初の短いチュートリアルステージを開く。必要な操作を盤面とタイルの反応で教え、長い説明文を常設しない。
2. タイルを置くたびに輪郭・隣接辺・頂点の制約を判定する。誤った操作では盤面を変えず、理由を短く示す。
3. 全領域が合法なタイルで埋まった瞬間にクリア演出を行い、完成形をタイトル兼ステージ選択画面の該当枠へ収める。
4. 以後はタイトル画面から次のステージ、未クリアのステージ、クリア済みのステージを選べる。進行に応じて新しい制約の読み方を学ぶ。
5. 最終的に、全ステージの完成形をタイトル画面で一覧できる。未クリア枠も同じ位置に残し、進捗がひと目で分かる。

ステージ数や章分けはレベルエディタで作成した公開データから決める。初版で固定の問題数を前提にしない。初回問題のクリア後は必ずタイトル画面へ遷移し、以降の通常ステージはタイトルへ戻る操作を持つ。最初の問題の初挑戦中だけは、導線を保つためタイトル・前後移動を隠す。

## 3. タイルと盤面

### 3.1 タイル

使用する形は P3 の `thin`（内角36°・144°）と `fat`（内角72°・108°）の2種類。タイルは同じ辺長を持つ。各タイルの4辺には `alpha` / `beta` と `convex` / `concave` の組を表す模様を持たせ、模様の意味は線の形と色の両方で判別できるようにする。初版の辺割り当てと頂点名は Penrosanne の `docs/tile-system.md` に合わせる。地形、道、都市、ミープル、得点は持ち込まない。

タイルは平面上で回転できる。回転時には輪郭・4辺の模様・4頂点の識別子が一体で動く。表裏反転、辺模様だけの独立回転、地形だけの回転は初版では使わない。同じ形に見える180°回転でも辺模様が違えば別の向きとして扱う。

### 3.2 ステージ盤面

ステージは、単純閉曲線の輪郭を持つ有限領域と、そこを埋めるタイル在庫からなる。輪郭は P3 ひし形の辺をつないで作り、直線上の各辺長はタイル1辺分とする。穴を持つ盤面は初版では対象外とする。盤面の内側は未配置の薄い面、輪郭は実線、外周模様は輪郭上の各辺に表示する。未配置領域と盤面の外を明度・輪郭で区別する。

タイルは盤面の境界内に完全に収まり、既存タイルと面積が重ならず、辺の接続点が一致する位置にだけ置ける。頂点だけの接触は辺の隣接とみなさない。配置座標と描画座標は同じ幾何モデルから求め、近似誤差による微小な隙間や重なりを見せない。

### 3.3 マッチングと合法配置

内部で2辺が接するとき、`alpha` 同士または `beta` 同士で、`convex` と `concave` が反対の場合に接続を許す。盤面外周に接する辺も、そこに印刷された模様と同じ条件で照合する。外周模様は装飾ではなく、盤外に固定された相手側の辺として扱う。

頂点型は Penrosanne の sun / moon / king / queen / jack / ace / deuce / star の循環順列を採用する。**盤面内部で周囲が埋まった頂点**は、該当する完成順列のいずれかと一致しなければならない。未完成の内部頂点は、残りの角度に適切なタイルを補える可能性がある場合だけ許す。**外周上の頂点**は盤外へタイルを補う必要がないため、盤内側の連続部分が少なくとも1つの許容頂点型と整合すればよい。外周の角度が頂点型を確定できない場合は、辺模様と幾何制約を優先する。この有限盤面向けの扱いはエディタの検証にも共通適用する。

配置候補は、輪郭内への収まり、非重複、全接触辺の模様一致、頂点型の整合、残り領域の充填可能性を順に検査する。残り領域の完全探索は重い場合があるため、プレイ中は明らかな不可能状態を検出する局所検査を必須とし、完全な解の有無はエディタの検証で確認する。候補がない在庫状態を許さないよう、公開前にステージ全体を検証する。

### 3.4 在庫とクリア

各ステージには薄い・厚いタイルの使用可能枚数を固定する。両者の枚数は公開解の構成と一致させる。プレイヤーは残数がある種類を選び、向きを変えて置く。置いたタイルは取り消し・置き直しできる。最後の1枚が合法配置され、輪郭内に未充填領域がなく、内部辺・外周辺・頂点の条件がすべて成立したときにクリアする。

模範配置と同じ位置に置くこと自体はクリア条件にしない。別解も条件を満たせばクリアとする。したがってステージデータの模範配置は盤面生成・検証・サムネイル用であり、プレイ中の正誤を「模範配置との一致」だけで決めない。

## 4. プレイ操作とフィードバック

- マウスでは在庫から種類を選び、盤面へドラッグまたは候補をクリックして仮置きする。タッチではタイルをつまんで運び、指を離して仮置きする。キーボードでもタイル種類・候補・回転・確定・取り消しを操作できるようにする。
- 回転は36°を基本刻みとし、実際に辺の方向と一致する候補だけを提示する。タイルを持ち上げている間は元の把持点を維持し、合法な着地点を硬い影で示す。
- 仮置き時には輪郭と辺模様を確認できる。確定前に回転、場所の変更、キャンセルができる。無効な位置で離した場合は手元へ戻す。
- 直前の配置を戻す、ステージを最初からやり直す、音のオン・オフを用意する。リセットは誤操作を避ける確認を挟む。
- ルール違反は短い視覚フィードバックとアクセシブルな文言で示す。失敗しても在庫を消費しない。解答そのものを常時表示しない。
- PCの画面サイズ、タッチ端末、拡大表示に対応する。色の識別だけに依存せず、模様の線形とラベルでも区別する。動きを減らす設定では持ち上げ・収納演出を即時完了できる。

## 5. 画面と視覚仕様

盤面とタイルを主役にする。タイル・主操作ボタンは、平坦な上面、画面下方向に見える暗い側面、硬い接地影で薄い立体物として描く。持ち上げ中は上面と側面を一緒に移し、接地影は盤面側に残す。側面や角丸は描画専用で、数学的なひし形の頂点・辺位置・当たり判定を動かさない。曖昧なぼかし、強い発光、ガラス風の面を基本デザインに使わない。色とフォントの具体値は画面モックで決め、役割別トークンとして管理する。

プレイ画面にはステージ番号、盤面、残りタイル、回転・戻る・リセット・タイトルへの操作を配置する。盤面の外周模様はタイルと重ならずに読める太さと間隔を確保する。タイトル兼ステージ選択画面には同じ比率のステージ枠を並べ、クリア済み枠には保存された完成盤面を縮小描画する。未クリア枠には輪郭のシルエットと番号を示す。全ステージを収めるため、枠数に応じたスクロールまたはページ切替を許し、全体の進捗も表示する。

## 6. ステージ進行と保存

初回起動判定、各ステージのクリア状態、最後に完成した配置、各ステージの途中配置を端末内に保存する。クリア済みステージを再挑戦しても、以前の完成形とクリア記録は新たなクリアまで保持する。途中配置は別領域に保存し、再開時に公開ステージの版と整合しなければ破棄する。ステージIDは表示順とは独立の永続IDとし、並べ替えによって進行記録が別問題へ移らないようにする。

公開ステージの追加・更新後も既存の完了記録を壊さないよう、ステージごとに版を持つ。輪郭・外周模様・在庫が変わる更新では途中配置を無効化し、過去の完成形は履歴として保持するか再検証して表示する。進行データ消去は確認後に行い、開発者の下書きは消さない。

## 7. レベルエディタ（開発の中核）

### 7.1 基本方針

レベルエディタはゲーム本体と同じ幾何・ルール判定を使う開発者画面とする。公開ステージ定義と編集中の下書きは分離する。下書きを変更しても通常プレイの問題は変わらず、検証済みデータを明示的に書き出して P3NROSE の公開ステージファイルへ反映した時だけゲームへ適用する。この関係は Symmetrica の開発者画面を参考にするが、手作業のコード貼り付けミスを防ぐため、初版はスキーマ付き JSON のインポート／エクスポートを正とする。

### 7.2 作問の手順

1. 新規ステージを作り、永続ID、表示名、表示順、章、短い学習テーマを設定する。既存ステージの複製・並べ替え・削除もできる。
2. キャンバス上で薄い・厚いタイルを回転・配置し、**完成形**を先に作る。エディタでも隣接辺と頂点型を逐次検査する。削除、移動、戻る・やり直し、拡大縮小、盤面のパンを用意する。
3. 完成形の外周を自動抽出し、各外周辺に接していたタイルの辺模様と対応する固定模様を自動生成する。輪郭・外周模様は同じ辺IDに紐づけ、見た目だけを編集して不一致を生じさせない。出題上の調整が必要なら固定模様を編集し、再検証する。
4. 完成形から薄い・厚いタイルの在庫数を自動集計する。必要に応じて開始時の固定配置、使用可能タイル種類、学習用の短い案内、サムネイル表示位置を指定する。
5. 「プレイヤーとして試す」で下書きを一時的に読み込み、通常プレイの操作と判定で解く。試遊を閉じると編集中の状態に戻る。
6. 検証結果を確認して公開データを書き出す。未検証・エラーのあるステージは公開出力に含めない。

### 7.3 検証と診断

エディタは少なくとも次を検査し、該当箇所を盤面上に示す。

- タイルの辺長・角度、重なり、離れた島、輪郭の自己交差、穴、微小な辺のずれ。
- 内部の辺模様、外周模様、内部・外周の頂点型、開始時の固定配置。
- 薄い・厚いタイルの在庫数と面積、完成形による1解の存在。
- 初期状態から少なくとも1手があり、最後まで到達できること。可能なら解探索で別解の有無と難度の目安を報告する。探索が制限時間に達したときは「未判定」と明示し、唯一解とは表示しない。
- チュートリアルの出題順と操作案内の前提が矛盾しないこと。

公開の必須条件は、完成形がすべてのルールを満たし、盤面の面積と在庫が一致し、通常プレイの初期状態からその完成形へ到達できることである。唯一解は必須としない。

### 7.4 データ形式と公開方法

公開データは `schemaVersion` とステージ配列を持つ JSON とし、ステージごとに `id`、`revision`、`order`、`chapter`、`name`、`learningGoal`、`solutionTiles`、`boundaryEdges`、`inventory`、`fixedTiles`、表示設定を保存する。幾何座標は浮動小数点を直接丸めて保存せず、ペンローズ辺方向に基づく正規化可能な離散座標または同等の正確な表現を使う。描画用ピクセル座標は保存しない。

ゲーム本体は起動時に公開 JSON を読み、スキーマと幾何を検証してステージ一覧を構築する。開発者画面の下書きは別キーで端末内に自動保存し、JSON の取り込み・書き出しができる。公開ファイルの差し替えは開発作業で行い、通常プレイヤーの保存データから公開ステージを変更できない。公開前の差分確認には追加・削除・順序変更・輪郭／外周模様の変更を表示する。

### 7.5 開発者画面の入口

通常プレイの画面から誤って開かない開発者専用の入口を設ける。開発中は明示的な開発用 URL または起動設定で開けるようにし、公開版では一般UIに入口を置かない。入口の隠し操作に安全性を依存しない。下書きの読み込み失敗時には公開データを壊さず、エラー内容と復旧用のエクスポートを提示する。

## 8. 実装の分割

- `game/geometry`：ひし形、離散座標、辺・頂点、外周抽出。
- `game/rules`：合法配置、在庫、完成判定、エディタ検証。DOM や Canvas に依存しない。
- `game/stages`：公開 JSON の読み込み、スキーマ検証、ステージIDと版管理。
- `ui/board`：プレイとエディタで共通の盤面描画、平面・側面・影。
- `ui/play`：操作、仮置き、演出、タイトル画面。
- `ui/editor`：作問、下書き、診断、試遊、インポート／エクスポート。
- `storage`：進行記録と開発下書きを別に管理。

この分割により、エディタで合法だった盤面がプレイ時に別判定になることを防ぐ。具体的なファイル名は実装時に確定する。

## 9. 初版の受け入れ条件

1. 新規ユーザーは起動直後に第1問を解き、クリア後にタイトル画面へ戻る。
2. 薄い・厚いタイルで輪郭内を埋め、外周を含む辺模様と頂点型を守った場合だけクリアする。別解もクリアになる。
3. 置けない位置ではタイルを消費せず、戻る・リセット・再開ができる。
4. タイトル画面にクリア済みステージの実際の完成形が表示され、全クリア後は全作品を一覧できる。
5. エディタで完成形を作ると輪郭・外周模様・在庫が生成され、検証、試遊、下書き保存、公開 JSON の書き出しまで行える。
6. 公開 JSON を読み込んだゲームとエディタの判定結果が一致する。ステージの並べ替えでは既存の進行記録が別問題へ移らない。
7. 平面と側面の立体表現が、PC・タッチ端末・拡大表示で一貫し、模様と操作状態が色だけに依存せず読める。

## 10. 実装前に試作で確定する点

- P3 の正確な離散座標表現と、有限輪郭の外周頂点に適用する許容条件。
- プレイ中の局所的な行き止まり検出範囲と、エディタの完全解探索の時間上限。
- 初回ステージの具体的な完成形と、その後の学習順・章構成。
- ステージ数に応じたタイトル画面の枠配置、色、フォント、効果音。

これらは試作と実際の作問で決める設計パラメータであり、第1問・レベルエディタ・共通ルールエンジンの実装を先送りする条件ではない。

## 11. レベルエディタ画面図に基づく追補（2026-10-14）

この節は、上の「完成形を先に作る」「在庫を固定する」「外周全辺の模様を自動生成する」という初版の記述より優先する。添付されたエディタ・ステージ画面の黄緑色のメモとユーザー指定を反映する。

- 各ステージは空の状態から開始する。THIN / FAT をタイル置き場からドラッグして最初のタイルを置く。2枚目以降は通常の合法配置に加え、エディタで探索された確定配置の位置とその隣接位置も作問に使える。置いたタイルは移動不可で、エディタの右クリックで削除する。
- タイルとボタンは上面・側面を持つ立体表現とし、タイルの角は Penrosanne に倣ってわずかに丸める。THIN の上面を暗色、FAT の上面を明色とし、タイル上のマッチング記号は円弧で描く。青は THIN の A / FAT の E を中心に辺長の25%、赤は THIN の C を中心に25%、FAT の G を中心に75%の半径とする。
- 「確定配置探索」は押したときにだけ、Penrosanne の高速な頂点テンプレート探索を実行する。結果は細線のタイルと赤青の円弧として描き、公開 JSON には含めない。
- 黄色い外周辺はエディタで自由に選択する。「外周自動作成」は確定配置を含む配置群の外側を選ぶ。黄色い辺は右クリックで削除、タイルまたは確定配置の辺を左クリックして追加する。元となるタイルや確定配置が消えたら、それに依存する黄色い辺も消す。
- 外周の記号は円弧でなく、タイルの円弧が辺と交わる点から盤面外へ延ばす直線とする。非表示の灰色点線、色を指定する赤／青の実線、色を指定しない灰色実線をクリックで巡回する。「記号ランダム選択」は各辺の表示状態をシャッフルする。灰色実線は、円弧が連続する赤または青のどちらも許す。
- 「初期表示タイル選択」はゲーム開始時から固定で存在するタイルを選ぶ。「全体を回転」は18°刻みの候補から角度を選ぶ。「全体リセット」はタイル・探索結果・外周を消去する。
- テストプレイには黄色い辺が分岐・交差のない1本の閉じた環を作ることが必要である。テストプレイボタンで本編風の画面に切り替え、戻るボタンでエディタへ戻す。本編のタイトルや進行はこの段階では実装しない。
- テストプレイではタイル置き場から枚数制限なくタイルを取り、外周の内側を埋める。固定以外の配置済みタイルはドラッグで再配置でき、盤外へのドロップで消せる。「すべてリセット」は固定タイルだけを残す。クリアは全領域がタイルで埋まり、表示されている盤外の直線記号の制約を満たした時とする。色を示さない記号では接続位置だけを判定する。画面上に常設のテキスト説明文を置かない。
- 盤面の床を外周より一段低く描き、奥側の内壁を床と外周の間に描く。床と壁は外周からはみ出さない。タイルの厚みは凹みの深さと同じとし、側面を面として描く。タイルは奥から手前へ描き、隣接タイルで覆われる側面と外周の壁に接する側面は隠す。
- 初期表示タイルはテストプレイでは内壁と同じ側面色で表示し、円弧の赤青は保つ。固定以外のタイルは枚数によらず右クリックで削除する。設置済みタイルを左クリックしただけでは新たなタイルを追加しない。
- 初期表示タイルの上面は背景色 #294845 とし、側面は内壁色を用いる。外周記号の灰色点線は編集時の表示候補であり、テストプレイでは描かない。
- テストプレイのタイル中央には、180°回転が合法なときだけ回転ボタンを表示する。配置の変更で回転が不可能になったら即座に隠す。右クリックは回転に用いず削除のままとする。
- 配置済みタイルを持ち上げて候補のない場所に落としたら取り除く。配置候補は既設タイルの隣だけでなく外周の各辺からも毎回求め、まだ連結していない部分配置も許す。
- 持ち上げ時は Penrosanne と同じく約100msで10px上昇させ、運搬中はタイル下と着地点に接地影を描く。候補への着地は約100msのイージングで位置・大きさ・向きを補間する。動きを減らす設定では時間補間を省略する。
- ステージの並べ替えは番号ボタンのドラッグで行う。下書きはローカル保存し、ステージ・固定タイル・外周とその表示状態・表示角度をJSONへ書き出す。
